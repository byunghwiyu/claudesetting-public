# 03. 코드 품질

## 단순성 강제 (Simplicity First)
- 요청된 것 **이상의 기능 / 추상화 / 유연성** 추가 금지
- 반복이 3회 이상이고 변경 이유가 동일할 때만 공통화·추상화를 검토한다. 한 번만 쓰는 코드를 위한 별도 추상화 레이어는 만들지 않는다.
- 가독성과 검증 가능성을 유지하면서 불필요한 복잡성과 중복을 줄인다. 줄 수 자체를 목표로 축약하지 않는다.
- "시니어 엔지니어가 이게 과하다고 할까?" — Yes면 다시 쓸 것

## 외과적 변경 (Surgical Changes)
- 변경된 **모든 줄**은 사용자 요청에 직접 연결되어야 함
- 관련 없는 인접 코드 "개선" 금지 — 건드리지 않은 코드가 최고의 코드
- 관련 없는 죽은 코드 / 포맷 / 주석은 **발견만 보고**, 수정 금지

## 설계 원칙
- 도메인 수치의 외부화 방식은 프로젝트 규칙을 우선하며, 글로벌 규칙에서는 특정 저장 형식을 강제하지 않는다.
- 데이터 처리는 **하드코딩 최소화**, 데이터 주도 방식으로 설계
- CSV/데이터 파일 처리 시 반드시 **헤더 유무 확인** 후 처리
- 자동화 스크립트는 **멱등성(idempotent)** 보장 — 여러 번 실행해도 안전하게
- 구조적 문제(중복 상태, 불일치 패턴, 아키텍처 결함) 발견 시 **반드시 지적하고 제안**하되, 구현은 명시적 승인 후에만

## PDF 처리 도구 선택

- PDF에서 텍스트·표·구조 추출이 필요하면 설치된 `opendataloader-pdf` CLI를 우선 검토한다.
- 사용 전에 `opendataloader-pdf --help`로 현재 버전의 출력 형식과 옵션을 확인한다. 이 공개본은 해당 도구를 설치하지 않는다.
- 변환된 Markdown을 먼저 읽고, 표 구조가 중요하면 JSON의 위치·구조 정보를 함께 확인한다.
- 스캔 PDF/OCR은 현재 CLI가 지원하는 hybrid 계열 옵션이나 사용 가능한 OCR 도구를 확인해 처리한다.
- 도구가 없거나 변환에 실패하면 사용 가능한 PDF 도구로 대체하고 한계를 보고한다. 외부 라이브러리 추가는 안전 규칙을 따른다.
- 단순 병합·분할은 설치된 PDF 도구로 처리한다. 특정 플러그인이 있다는 전제로 호출하지 않는다.

## C# Unity 네이밍 컨벤션
- `private` 필드: `_camelCase`
- `public` 프로퍼티 / 메서드: `PascalCase`
- 지역 변수 / 파라미터: `camelCase`
- 상수: `ALL_CAPS` (또는 `PascalCase` — 프로젝트 기존 스타일 우선)
- 위반 발견 시 해당 파일 수정 범위 내에서 함께 교정할 것
