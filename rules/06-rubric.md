# 06. 루브릭 기반 완료 판정

> 이 규칙은 Claude(`~/.claude/rules/06-rubric.md`)와 Codex(`~/.codex/AGENTS.md`)에
> 함께 설치한 경우 **동일 내용으로 유지**한다. 단독 설치에서는 존재하지 않는 상대 설정을 생성하지 않는다.

## 철학
- "완료"는 자기 선언이 아니라 **사전에 선언한 기준의 통과**로 판정한다
- 채점은 0~100 점수가 아니라 **항목별 Yes/No 체크리스트** — 숫자 자기 채점은 부풀려진다

## 작업 착수 전 — 성공 기준 선언 (비자명 작업 전부)
1. 아래 **공통 기본 루브릭**을 바탕으로, 요청문에서 작업 특화 기준을 더해
   **총 3~7개**를 계획 설명에 포함해 선언한다
2. 각 기준은 Yes/No 판정 가능해야 함 ("깔끔한가" ❌ / "예외 케이스 테스트 존재" ⭕)
3. 사용자가 기준을 교정하면 그것이 최종 루브릭
4. 실행 중인 스킬에 자체 루브릭이 있으면 해당 스킬 작업에서는 스킬 루브릭이 우선

## 공통 기본 루브릭 (모든 작업 공통 축)
| 축 | 판정 질문 |
|---|---|
| 의도 충족 | 원 요청의 의도를 충족했는가 (문구가 아니라 목적 기준) |
| 완전성 | 요청된 항목이 하나도 누락 없이 처리됐는가 |
| 정확성 | 수치·경로·참조·사실이 실제로 검증됐는가 (추정 금지) |
| 정합성 | 기존 구조·컨벤션·다른 규칙과 충돌하지 않는가 |
| 외과성 | 요청 범위 밖 변경이 없는가 |

## 완료 보고 전 — 자기 채점과 gap 보수
- 기준별 통과/미달 채점 → 미달 항목은 **빠진 것(gap)을 명시**하고 그 항목만 보수
- 전체 재생성 금지 — gap 보수만. 재작업 최대 2회
- 2회 후에도 미달이면 미달 항목·시도 내역과 함께 사람에게 보고
- 완료 보고에 기준별 판정을 1줄씩 첨부

## 경계
- 코드의 빌드/포맷은 프로젝트의 필수 검증 절차가 담당하며 루브릭은 내용 품질을 확인한다.
- 단순 질문과 의미 변화 없는 사소한 수정에는 미적용한다. 파일이 하나여도 동작·데이터·보안에 영향을 주는 비자명 변경에는 적용한다.

## 공통 하네스 계약 (자동 생성)

> 원본: ~/.codex/harness-policy.json — 이 블록을 직접 수정하지 않는다.

- 항상 한국어로 대화한다.
- 읽기·조사·분석은 진행한다. 변경 작업은 계획과 성공 기준을 설명하고 승인받는다. 승인한 범위의 일반 편집·관련 오류 교정은 재승인 없이 진행한다. 승인 범위를 벗어나거나 저장 방식·공개 API·사용자 경험의 큰 결정이 필요하면 선택지와 추천 이유를 제시하고 확인받는다. 이 계약은 글로벌 문서의 포괄적인 작업 전 확인·가정 확인 문구를 구체화하며 승인 범위 해석에 우선한다.
- 삭제·기존 내용의 전면 교체·운영 데이터 변경·결제·배포·강제 Git 작업은 대상과 영향을 명시해 승인받는다. 이미 동일 대상과 행위를 명시적으로 승인받았다면 반복 확인하지 않는다. 일반 편집은 전면 교체로 보지 않는다. 실행 정책의 차단은 대화상 승인으로 해제되지 않으며 우회하지 않는다.
- 1 Phase의 변경 파일은 최대 5개다.
- 각 Phase 완료 후 검증 결과를 보고하고 다음 Phase 전에 명시적 승인을 받는다.
- 비자명 작업은 착수 전에 Yes/No로 판정 가능한 성공 기준 3~7개를 선언한다.
- 공통 판정 축: 의도 충족, 완전성, 정확성, 정합성, 외과성
- 완료 보고 전 기준별 Yes/No 판정과 검증 근거를 확인한다.
