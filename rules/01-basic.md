# 01. 기본 규칙 + 컨텍스트 안전

## 대화 기본
- 항상 **한국어**로 대화할 것
- 읽기·조사·분석은 진행한다. 변경 작업은 **계획과 성공 기준을 설명**하고 승인받는다.
- 승인 범위 안의 일반 편집·관련 오류 교정은 재승인 없이 진행한다. Phase 전환 승인은 실행 규칙을 따른다.
- 삭제·기존 내용의 전면 교체는 대상과 영향을 명시해 승인받는다. 이미 승인한 동일 작업은 반복 확인하지 않는다.
- 코드 변경 시 **변경 전/후 차이**를 명확히 설명할 것
- 한국어 주석처리 해주고 한글 깨지지 않게 항상 체크할 것
- 불분명한 사항은 가정을 명시한다. 승인 범위 안의 되돌릴 수 있는 선택은 판단 근거를 남기고 진행한다.
- 승인 범위를 벗어나거나 저장 방식·공개 API·사용자 경험의 큰 결정이 필요하면 선택지와 추천 이유를 제시하고 확인받는다.

## 파일 편집 컨텍스트 안전
- 편집 전 반드시 파일 재읽기, 편집 후 재읽기로 적용 확인
- 동일 파일 3회 이상 연속 편집 시 중간 검증 읽기 수행
- 500줄 이상 파일은 offset/limit 파라미터로 청크 단위 읽기

## 컨텍스트 감쇠 대응
- 대화 10회 이상 경과 시 파일 편집 전 반드시 재읽기 (압축으로 인한 stale 상태 방지)
- 검색/명령 결과가 의심스럽게 적으면 범위를 좁혀 재실행, 잘림(truncation) 의심 시 명시

## 심볼 변경 시 전방위 grep
클래스/메서드/변수명 변경 시 아래 항목 **각각 별도로** 검색:
- 직접 호출 및 참조
- using / namespace 선언
- 문자열 리터럴 포함 여부
- 재export / 배럴 파일 항목
- Unity의 `SerializeField`, `Resources.Load`, 프리팹/씬 연결 영향 여부
