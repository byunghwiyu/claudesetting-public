# 04. 안전·금지·위험 작업

## 금지 사항
- 확인 없이 프로덕션 데이터 수정 금지
- 외부 라이브러리 추가 시 반드시 사전 고지
- 승인 없이 대규모 리팩토링 금지
- 컴파일 에러 또는 포매팅 위반 상태를 완료로 보고 금지
- 요청과 무관한 코드(인접 메서드, 주석, 포맷 등) 수정 금지

## 위험 작업 Deny List
**동작 전제**: 정책 파일과 차단 훅이 포함돼 있다. 실제 자동 차단은 설치·등록된 훅과 현재 도구의 호출 경로에 달려 있으므로, 파일이 있다는 이유만으로 보호가 활성화됐다고 가정하지 않는다.

설치한 뒤에는 정책 로드, 도구별 훅 등록, 차단·허용 사례를 검증한다. 자동 차단 여부는 실제 설치된 정책과 검사 결과로 판단한다.

### 자동 차단 정책으로 검증할 보호 대상 (실행 정책의 차단은 우회 금지)
- `git push --force` / `-f` / `--force-with-lease` — 협업 브랜치 손실 위험
- `git reset --hard` — uncommitted 변경 손실
- `rm -rf` 대량 삭제 / `sudo` 관리자 명령
- `rm`으로 Unity 핵심 디렉토리(`Assets/`, `ProjectSettings/`, `Packages/`) 건드림
- `DROP TABLE` / `DROP DATABASE` / `DROP SCHEMA` / `TRUNCATE` (Bash 또는 `.sql/.cs/.ts/.py` 등 코드 Write/Edit)
- 패키지 게시: `npm publish` / `pnpm publish` / `yarn publish`
- GitHub 릴리스 생성: `gh release create`
- API 키·토큰 패턴(`sk-…`, `ghp_…`, `AIza…`, `xox[baprs]-…`) Bash/Write/Edit
- 테스트 코드(`test/`, `*.test.*`)에서 `process.env.PROD` 접근

### 자동 차단에 의존하지 않고 작업 전 확인할 대상
- 실제 결제 처리 / 배포 스크립트 실행
- `git tag -a` (annotated 태그) — 릴리스 워크플로우 일부, 일상 사용 빈도로 미차단
- Unity 핵심 디렉토리 **Write/Edit** 대량 변경 (rm이 아닌 편집은 미차단)
- 외부 라이브러리 추가, 프로덕션 설정 변경

## 사고 발생 시 운영 규칙

1. 실패 원인과 재현 조건을 기록하고, 정책 변경 대상과 영향을 설명해 승인받는다.
2. 정책 변경은 공통 원본 `safety-policy.json`에서 수행하고 생성 도구로 Claude·Codex 산출물을 갱신한다. 생성된 `deny-patterns.json`을 직접 수정하지 않는다.
3. 공통 원본과 생성 도구는 Codex 공개본에서 관리한다. Claude만 사용하는 경우 정책 변경 전에 해당 원본과 생성 도구를 준비한다. 임의의 개인 설정에 변경을 적용하지 않는다.
4. 차단 사례와 정상 허용 사례를 모두 검증한다. 기억이나 문서만으로 재발 방지를 완료했다고 보고하지 않는다.
5. 실행 정책의 차단은 대화상 승인으로 해제되지 않는다. 차단 원인을 보고하고 허용된 대안을 제시한다.
